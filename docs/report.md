# 言葉で頼めるお片付けロボットアーム

## 1. 概要

日本語の指示（例：「赤い箱を青い皿に置いて」）を受けて、シミュレータ上のロボットアームが机の上の物をつかみ、指定の皿へ運ぶ。指示の解釈には大規模言語モデル Claude を推論だけで使い、学習は行わない。全体を ROS 2 のノードに分け、評価も ROS 2 の上で行った。

- 結果：28通りの指示 × 物の配置5通りで、日本語の指示は140回中135回成功（96%）。同じ指示を英語にしても135回で、結果が食い違った組は無かった
- 動画：〔YouTube の URL〕
- コード：〔GitHub の URL〕

## 2. 目的と問い

〔要記入：なぜ言葉で頼めるとよいか。家庭や職場の片付けで、物の名前・色・位置関係で頼みたい場面。〕

次の4つの問いに答えることを目的とした。

1. **日本語の指示をどこまで正しく実行できるか**：言い換え、複数の物をまとめた指示、「一番左の物」のように配置を見ないと決まらない指示を含める
2. **実行できない指示や曖昧な指示を、勝手に動かずに断れるか**：存在しない物・存在しない皿・どれを指すか決まらない指示
3. **指示の言語（日本語・英語）で振る舞いが変わるか**：同じ意味の指示を英語にして、同じ配置で比べる
4. **言語で指示する方式と、手本を真似る模倣学習（ACT）は、それぞれ何に向くか**

### 関連するサンプルとの違い

<!-- サンプルの記事の中身を読み直して、言い方を確かめてから提出する -->
講座のサンプルのうち、Gemini Robotics-ER を試す記事と ChatGPT API で自然言語からロボットを操作する記事が、考え方の近いものに当たる。本研究はそれらのコードを使わずに作り、言語モデルの答えを画素の座標に限り、3次元位置への変換と動作はプログラムが受け持つ形にした。そのうえで、断るべき指示と言語の違いを含めて、数百回の試行で成功率と失敗の種類を数えた。

## 3. 仕組み

〔図：指示＋真上画像 → Claude → 画素の座標 → 机上の3次元位置 → IK → 把持・運搬〕

| 段 | 内容 |
|---|---|
| シミュレータ | MuJoCo。Franka Panda（MuJoCo Menagerie）と、皿2枚・物3個（赤い箱・紫の箱・緑の円柱）を置いた机 |
| 観測 | 真上のカメラ1台の画像（640×480） |
| 計画 | Claude に画像と指示を渡し、運ぶ物の上面中心と置き先の皿の中心を画素で返させる（構造化出力）。実行できない指示には理由を返させる |
| 座標変換 | カメラの位置・向き・画角からピンホールモデルで画素を机上の点へ戻す |
| 動作 | 減衰最小二乗の IK で、真下向きの手先を目標へ動かしてつかみ、運び、離す |

### 3.1 ROS 2 のノード構成

実行環境は講義と同じ ROS 2 Humble の Docker イメージ（Ubuntu 22.04）。計画・座標変換・動作は ROS に依存しない Python のコードとして書き、ノードはそれを呼び出すだけにした。

| ノード | 役割 | ROS 2 でのやりとり |
|---|---|---|
| sim | シミュレータを持ち、実機ならロボットとカメラのドライバに当たる | 真上・正面の画像と関節角を topic で送る。運搬を action `/pick_place` で受け、途中の段階（近づく・つかむ・運ぶ・離す・戻る）を feedback で返す。配置の作り直しと、物と皿の位置・物がどの皿にあるかを service で答える |
| planner | 計画係 | 真上画像を topic で受け取り、指示を action `/plan` で受けて Claude に計画させ、画素を机上の点へ戻して返す |
| tidy | 指示を出す側 | 指示1つを受け、計画 → 運搬（物ごと）→ 結果の確認を順に呼ぶ |
| evaluate | 評価 | tidy と同じ呼び出しを、指示・配置・言語を変えながら繰り返し、結果を採点して記録する |

カメラとアームは同じシミュレータの世界を共有するため、sim に1つにまとめた。実機に移すときは、sim を実機のドライバに置き換え、planner のカメラの位置・画角を実機の較正値に差し替えれば、残りはそのまま使える分け方にしている（実機では試していない）。

## 4. 工夫した点

1. **画素で答えさせ、座標の計算はプログラムが受け持つ**：〔要記入：LLM に3次元座標を直接言わせない理由〕。つかむ点の誤差は平均 0.22cm・最大 0.5cm に収まった
2. **断れることを評価に入れた**：存在しない物・曖昧な指示には計画を出さず理由を返すのを正解とした
3. **僅差の配置の扱い**：位置関係で比べる距離の差が 2cm 未満なら、どれを選んでも、判断を保留しても正解とした。人が見ても決められない配置で、迷いを伝えられることを長所として扱うため
4. **正解計画との比較**：正解の位置から作った計画を同じ経路で実行し（3配置で 84/84）、失敗が「解釈」と「動作」のどちらで起きたかを分けた
5. **シミュレーションの不具合への対処**：円柱が指に引っかかって離れない現象の原因が衝突判定の設定（multiccd）にあると突き止め、無効にした 〔要記入：前後の成功率〕
6. **言語の比較は指示文だけを変えた**：Claude への説明文（システムプロンプト）は日本語のまま固定し、指示文だけを英語にした。変える条件を1つにして、差が出たら指示の言語によると言えるようにするため。英語の指示は意味をそろえて訳し、日本語の正解をそのまま使った。ただし「箱を青い皿へ」は、日本語では箱1つとも全部とも読めるが、英語の "The box" は1つに決まるので、英語では保留だけを正解とした
7. **ROS に依存しない中身と、薄いノード**：採点の規則も ROS に依存しないコードにして、ROS を使わない版と ROS 2 版で同じものを使った。ROS を使わない版で先に評価した結果（140回中135回）と、ROS 2 版の日本語の結果は一致した

## 5. 評価

### 5.1 方法

- 指示28通り：基本6・言い換え6・複数5・位置関係5・実行できない/曖昧6。それぞれに英語の指示を用意した
- 物と皿の配置を乱数で5通り変え、配置ごとに日本語と英語を続けて試した（計280回）
- 1回の流れ（evaluate ノード）：配置を作り直す → 物と皿の位置を取得して正解を求める → 計画させる → つかむ点を机上へ戻して採点する → 計画が正しければ運ぶ → どの物がどの皿に載ったかを確かめる
- 判定：正解の物が正解の皿に載れば成功。失敗は「計画を得られない」「物の取り違え」「置き先の誤り」「件数の誤り」「断るべきなのに動いた」「つかみ損ね」に分ける
- シミュレータは実時間に合わせず、最速で回した

### 5.2 問い1・2：日本語の指示を実行できるか、断れるか

| 区分 | 日本語 | 英語 |
|---|---|---|
| 基本 | 30/30 | 30/30 |
| 言い換え | 30/30 | 30/30 |
| 複数 | 25/25 | 25/25 |
| 位置関係 | 25/25 | 25/25 |
| 実行できない/曖昧 | 25/30 | 25/30 |
| 合計 | 135/140 | 135/140 |

- 実行すべき指示（基本・言い換え・複数・位置関係）は、日本語・英語とも全問成功した。うち位置関係の3回（日本語2回・英語1回）は、比べる距離がほぼ同じ配置で、Claude が「どちらが一番近い物か決められません」と保留した（正解として扱った）
- 断るべき指示の失敗5件は、日本語・英語ともすべて「ボールを青い皿へ」で、緑の円柱を「緑のボール」として運んだもの
- 1回の計画にかかった時間：平均 3.4秒（日本語）・3.3秒（英語）
- つかむ点の誤差：平均 0.22cm・最大 0.5cm（両言語とも）

### 5.3 問い3：指示の言語で振る舞いが変わるか

同じ指示・同じ配置の140組で比べると、成功か失敗か、失敗の種類まで、すべての組で一致した。計画の時間や、Claude の返答の長さ（出力トークン数の平均 133 と 127）にも大きな差は無かった。

振る舞いが分かれたのは「箱を青い皿へ」（英語 "The box to the blue plate"）だけだった。

| | 箱を2つとも運んだ | 保留した |
|---|---|---|
| 日本語「箱を青い皿へ」 | 2回 | 3回（3回とも「どちらを（または両方を）運ぶのか決められません」） |
| 英語 "The box to the blue plate" | 0回 | 5回（5回とも「どちらを指すか決められません」） |

日本語の名詞には単数・複数の区別が無いため、Claude は「箱を」を全部の箱とも読み、保留するときも「両方」の可能性に触れた。英語では冠詞と単数形で1つに決まるため、2つとも運ぶことは一度も無く、どちらか1つを尋ねる形で保留した。Claude は指示の文法から数を読み取っており、日本語では数の曖昧さが残りやすいと言える。

なお、返答は英語の指示でも日本語で書かれた（説明文が日本語のため）。紫の箱を「ピンクの箱」と呼ぶなど、物の呼び方の癖も言語によらず同じだった。

### 5.4 問い4：模倣学習（ACT）との比較

言葉を使わずに、手本の動きを真似る学習だけで同じ作業ができるかを比べた。ACT（Action Chunking with Transformers）は言葉を受け取らないため、課題は「赤い箱を青い皿へ」の1つに固定した。この比較は ROS を使わない版で行った。

- 手本：IK で動かした成功例 200本（物の配置を変えて収集。0.1秒ごとに真上画像・関節の状態・次の目標の関節角と指の開閉を記録。計 19,383 コマ）
- モデル：ACT を小さく自作した（画像の特徴抽出に ResNet18、Transformer の符号化器4層・復号器1層、2秒分 20 コマの動きをまとめて予測）
- 学習：Google Colab の無料 GPU（T4）で 20,000 歩・約36分。検証データの誤差（L1）は 7,500 歩でほぼ下げ止まり、最終 0.085
- 評価：学習に使っていない配置 20 通りで、3つの方式を同じ配置で比べた

| 方式 | 成功 | 備考 |
|---|---|---|
| IK（正解の位置を与える） | 20/20 | 手本を作った方式。上限の目安 |
| Claude ＋ IK（本研究の方式） | 20/20 | 画像から位置を読み取る |
| ACT（模倣学習） | 13/20 | 失敗7件はすべてつかみ損ね |

ACT の失敗7件は、どれも箱を持ち上げられなかったもの（つかみ損ね）で、運ぶ先を誤った例は無かった。学習途中の 12,000 歩の時点でも評価し（12/20）、最終と比べると失敗した配置は大半が入れ替わり、両方で失敗したのは3配置だけだった。特定の配置が苦手というより、つかむ直前の数 cm のずれが確率的に生じていると考える。

## 6. 考察

- **問い1（実行できるか）**：言い換えや位置関係を含め、実行すべき指示は全問成功した。画素で答えさせて座標はプログラムが求める分担にしたことで、つかむ位置のずれは 0.5cm 以内に収まり、動作の失敗は1回も無かった。
- **問い2（断れるか）**：存在しない物・皿、「さっきの箱」のように文脈が要る指示は、すべて理由を添えて断れた。断れなかったのは「ボールを青い皿へ」だけで、真上からは円柱が円に見えるため、Claude は緑の円柱をボールとして運んだ。これは言葉の理解ではなく、真上1枚の画像という視点の限界による。〔要記入：横からのカメラを足す・形を尋ね返す などの改善案〕
- **問い3（言語で変わるか）**：成功率は言語で変わらず、指示の意味さえ伝われば日本語でも英語と同じように動かせた。違いは数の曖昧さに表れた。日本語の「箱を」は全部の箱とも読めるため、2回は箱を2つとも運んだ。安全側に倒すなら、日本語の指示で対象が複数あり得るときは確認を求める、といった扱いを計画係の説明文に足すのがよい。ただし、英語の指示は筆者の訳で、配置も5通りと少ないため、言語による差がこの1件だけとは言い切れない。
- **問い4（模倣学習との向き不向き）**：ACT は手本 200本と 36分の学習で、運ぶ動きの流れ（近づく・つかむ・運ぶ・離す）は身に付けたが、つかむ位置の精度が足りず 13/20 にとどまった。学習時の計算を軽くするため真上画像を半分（320×240）に縮めており、一辺 4.4cm の箱が画像上では一辺 12 画素ほどしか無いことが一因と考える。改善の候補は、効果が大きそうな順に、手首にカメラを付けて手元を大きく映す・手本を増やす・画像の解像度を上げる、の3つ。一方、本研究の方式は位置を画素で読み取ってから IK で動かすため、学習なしで同じ配置を 20/20 こなし、指示を変えれば別の物・別の皿にも応じられ、問い2・3のように断ることもできる。ただし動作は IK の決まった手順に限られ、柔らかい物や引き出しの開閉のように手順を書きにくい動きは、模倣学習のほうが向く。
