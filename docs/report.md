# 言葉で頼めるお片付けロボットアーム

<!-- 骨組み。〔要記入〕を埋め、数字は評価を足したら差し替える。PDF 化して提出する（A4・3〜5ページ目安）。 -->

## 1. 概要

日本語の指示（例：「赤い箱を青い皿に置いて」）を受けて、シミュレータ上のロボットアームが机の上の物をつかみ、指定の皿へ運ぶ。指示の解釈には大規模言語モデル Claude を推論だけで使い、学習は行わない。

- 結果：28通りの指示 × 物の配置5通りで、140回中135回成功（96%）
- 動画：〔YouTube の URL〕
- コード：〔GitHub の URL〕

## 2. 目的

〔要記入：なぜ言葉で頼めるとよいか。家庭や職場の片付けで、物の名前・色・位置関係で頼みたい場面。〕

確かめたいことは次の3点。

1. 色・形の呼び方を変えた言い換えや、複数の物をまとめて頼む指示に応じられるか
2. 「一番左の物」のように、配置を見ないと決まらない指示に応じられるか
3. 存在しない物や、どれを指すか決まらない指示を、勝手に動かずに断れるか

## 3. 仕組み

〔図：指示＋真上画像 → Claude → 画素の座標 → 机上の3次元位置 → IK → 把持・運搬〕

| 段 | 内容 |
|---|---|
| シミュレータ | MuJoCo。Franka Panda（MuJoCo Menagerie）と、皿2枚・物3個（赤い箱・紫の箱・緑の円柱）を置いた机 |
| 観測 | 真上のカメラ1台の画像（640×480） |
| 計画 | Claude に画像と指示を渡し、運ぶ物の上面中心と置き先の皿の中心を画素で返させる（構造化出力）。実行できない指示には理由を返させる |
| 座標変換 | カメラの位置・向き・画角からピンホールモデルで画素を机上の点へ戻す |
| 動作 | 減衰最小二乗の IK で、真下向きの手先を目標へ動かしてつかみ、運び、離す |

### 3.1 ROS 2 版

同じ処理を ROS 2 のノードに分けた版も作った。実行環境は講義と同じ ROS 2 Humble の Docker イメージ（Ubuntu 22.04）で、計画・座標変換・動作のコードは上の版をそのまま使い、ノードはそれを呼び出すだけにした。

| ノード | 役割 | ROS 2 でのやりとり |
|---|---|---|
| sim | シミュレータを持ち、実機ならロボットとカメラのドライバに当たる | 真上・正面の画像と関節角を topic で送る。運搬を action `/pick_place` で受け、途中の段階（近づく・つかむ・運ぶ・離す・戻る）を feedback で返す。配置の作り直しと、物がどの皿にあるかを service で答える |
| planner | 計画係 | 真上画像を topic で受け取り、指示を action `/plan` で受けて Claude に計画させ、画素を机上の点へ戻して返す |
| tidy | 指示を出す側 | 指示1つを受け、計画 → 運搬（物ごと）→ 結果の確認を順に呼ぶ |

カメラとアームは同じシミュレータの世界を共有するため、sim に1つにまとめた。実機に移すときは、sim を実機のドライバに置き換え、planner のカメラの位置・画角を実機の較正値に差し替えれば、tidy を含む残りはそのまま使える分け方にしている（実機では試していない）。

## 4. 工夫した点

1. **画素で答えさせ、座標の計算はプログラムが受け持つ**：〔要記入：LLM に3次元座標を直接言わせない理由。カメラの式で誤差が平均 0.3cm 程度に収まった〕
2. **断れることを評価に入れた**：存在しない物・曖昧な指示には計画を出さず理由を返すのを正解とした
3. **僅差の配置の扱い**：位置関係で比べる距離の差が 2cm 未満なら、どれを選んでも、判断を保留しても正解とした。人が見ても決められない配置で、迷いを伝えられることを長所として扱うため
4. **正解計画との比較**：正解の位置から作った計画を同じ経路で実行し（3配置で 84/84）、失敗が「解釈」と「動作」のどちらで起きたかを分けた
5. **シミュレーションの不具合への対処**：円柱が指に引っかかって離れない現象の原因が衝突判定の設定（multiccd）にあると突き止め、無効にした 〔要記入：前後の成功率〕
6. **ROS に依存しない中身と、薄いノード**：計画・座標変換・動作は ROS を使わずに書き、評価もその形で行った。ROS 2 版のノードはそれを呼ぶだけなので、評価した処理と同じものが ROS 2 の上で動く

## 5. 評価

### 5.1 方法

- 指示28通り：基本6・言い換え6・複数5・位置関係5・実行できない/曖昧6
- 物と皿の配置を乱数で5通り変える（計140回）
- 判定：正解の物が正解の皿に載れば成功。失敗は「計画を得られない」「物の取り違え」「置き先の誤り」「件数の誤り」「断るべきなのに動いた」「つかみ損ね」に分ける

### 5.2 結果

| 区分 | 成功 |
|---|---|
| 基本 | 30/30 |
| 言い換え | 30/30 |
| 複数 | 25/25 |
| 位置関係 | 25/25 |
| 実行できない/曖昧 | 25/30 |
| 合計 | 135/140 |

- 1回の計画にかかった時間：平均 3.2秒
- つかむ点の誤差：平均 0.24cm・最大 0.5cm

### 5.3 追加実験：模倣学習（ACT）との比較

言葉を使わずに、手本の動きを真似る学習だけで同じ作業ができるかを比べた。ACT（Action Chunking with Transformers）は言葉を受け取らないため、課題は「赤い箱を青い皿へ」の1つに固定した。

- 手本：IK で動かした成功例 200本（物の配置を変えて収集。0.1秒ごとに真上画像・関節の状態・次の目標の関節角と指の開閉を記録。計 19,383 コマ）
- モデル：ACT を小さく自作した（画像の特徴抽出に ResNet18、Transformer の符号化器4層・復号器1層、2秒分 20 コマの動きをまとめて予測）
- 学習：Google Colab の無料 GPU（T4）で 20,000 歩・約36分。検証データの誤差（L1）は 7,500 歩でほぼ下げ止まり、最終 0.085
- 評価：学習に使っていない配置 20 通りで、3つの方式を同じ配置で比べた

| 方式 | 成功 | 備考 |
|---|---|---|
| IK（正解の位置を与える） | 20/20 | 手本を作った方式。上限の目安 |
| Claude ＋ IK（本研究の方式） | 20/20 | 画像から位置を読み取る |
| ACT（模倣学習） | 13/20 | 失敗7件はすべてつかみ損ね |

ACT の失敗7件は、どれも箱を持ち上げられなかったもの（つかみ損ね）で、運ぶ先を誤った例は無かった。学習途中の 12,000 歩の時点でも評価し（12/20）、最終と比べると失敗した配置は大半が入れ替わり、両方で失敗したのは3配置だけだった。特定の配置が苦手というより、つかむ直前の数 cm のずれが確率的に生じていると考える。

### 5.4 ROS 2 版の動作確認

ROS 2 版（3.1）は通しで動くことだけを確かめた。成功率の評価（5.2）は ROS を使わない版で行っており、ROS 2 版では数を回していない。

- 「赤い箱を青い皿に置いて」（配置3）：赤い箱が青い皿に載った
- 「全部の物を黄色い皿に置いて」（配置5）：Claude が3回の運搬に分け、3つとも黄色い皿に載った。計画に 10.4秒、運搬は実時間に合わせて動かし1回 約15秒

## 6. 考察

- **真上1枚の画像の限界**：「ボールを青い皿へ」で、Claude は緑の円柱を「緑のボール」として運んだ。真上からは円柱が円に見えるため。失敗5件はすべてこの指示で、5配置とも同じ誤りだった。〔要記入：横からのカメラを足す・形を尋ね返す などの改善案〕
- **指示の曖昧さ**：「箱を青い皿へ」は、箱1つとも全部とも読める。5配置のうち3回は「どちらを（または両方を）運ぶのか決められない」と返し、2回は箱を2つとも運んだ。どちらも正解として扱った。
- **僅差の配置**：140回中2回、Claude は「緑の玉と赤い箱はロボットの根元からの距離がほぼ同じで、どちらが一番近い物か決められません」のように保留した。実測の差は 0.1cm と 0.4cm で、人が見ても決められない配置だった。
- **模倣学習との違い**：ACT は手本 200本と 36分の学習で、運ぶ動きの流れ（近づく・つかむ・運ぶ・離す）は身に付けたが、つかむ位置の精度が足りず 13/20 にとどまった。学習時の計算を軽くするため真上画像を半分（320×240）に縮めており、一辺 4.4cm の箱が画像上では一辺 12 画素ほどしか無いことが一因と考える。改善の候補は、効果が大きそうな順に、手首にカメラを付けて手元を大きく映す・手本を増やす・画像の解像度を上げる、の3つ。一方、本研究の方式は位置を画素で読み取ってから IK で動かすため、学習なしで同じ配置を 20/20 こなし、指示を変えれば別の物・別の皿にも応じられる。ただし動作は IK の決まった手順に限られ、柔らかい物や引き出しの開閉のように手順を書きにくい動きは、模倣学習のほうが向く。
