# 言葉で頼めるお片付けロボットアーム

<!-- 骨組み。〔要記入〕を埋め、数字は評価を足したら差し替える。PDF 化して提出する（A4・3〜5ページ目安）。 -->

## 1. 概要

日本語の指示（例：「赤い箱を青い皿に置いて」）を受けて、シミュレータ上のロボットアームが机の上の物をつかみ、指定の皿へ運ぶ。指示の解釈には大規模言語モデル Claude を推論だけで使い、学習は行わない。

- 結果：28通りの指示 × 物の配置5通りで、140回中135回成功（96%）
- 動画：〔YouTube の URL〕
- コード：〔GitHub の URL〕

## 2. 目的

〔要記入：なぜ言葉で頼めるとよいか。家庭や職場の片付けで、物の名前・色・位置関係で頼みたい場面。〕

確かめたいことは次の3点。

1. 色・形の呼び方を変えた言い換えや、複数の物をまとめて頼む指示に応じられるか
2. 「一番左の物」のように、配置を見ないと決まらない指示に応じられるか
3. 存在しない物や、どれを指すか決まらない指示を、勝手に動かずに断れるか

## 3. 仕組み

〔図：指示＋真上画像 → Claude → 画素の座標 → 机上の3次元位置 → IK → 把持・運搬〕

| 段 | 内容 |
|---|---|
| シミュレータ | MuJoCo。Franka Panda（MuJoCo Menagerie）と、皿2枚・物3個（赤い箱・紫の箱・緑の円柱）を置いた机 |
| 観測 | 真上のカメラ1台の画像（640×480） |
| 計画 | Claude に画像と指示を渡し、運ぶ物の上面中心と置き先の皿の中心を画素で返させる（構造化出力）。実行できない指示には理由を返させる |
| 座標変換 | カメラの位置・向き・画角からピンホールモデルで画素を机上の点へ戻す |
| 動作 | 減衰最小二乗の IK で、真下向きの手先を目標へ動かしてつかみ、運び、離す |

## 4. 工夫した点

1. **画素で答えさせ、座標の計算はプログラムが受け持つ**：〔要記入：LLM に3次元座標を直接言わせない理由。カメラの式で誤差が平均 0.3cm 程度に収まった〕
2. **断れることを評価に入れた**：存在しない物・曖昧な指示には計画を出さず理由を返すのを正解とした
3. **僅差の配置の扱い**：位置関係で比べる距離の差が 2cm 未満なら、どれを選んでも、判断を保留しても正解とした。人が見ても決められない配置で、迷いを伝えられることを長所として扱うため
4. **正解計画との比較**：正解の位置から作った計画を同じ経路で実行し（3配置で 84/84）、失敗が「解釈」と「動作」のどちらで起きたかを分けた
5. **シミュレーションの不具合への対処**：円柱が指に引っかかって離れない現象の原因が衝突判定の設定（multiccd）にあると突き止め、無効にした 〔要記入：前後の成功率〕

## 5. 評価

### 5.1 方法

- 指示28通り：基本6・言い換え6・複数5・位置関係5・実行できない/曖昧6
- 物と皿の配置を乱数で5通り変える（計140回）
- 判定：正解の物が正解の皿に載れば成功。失敗は「計画を得られない」「物の取り違え」「置き先の誤り」「件数の誤り」「断るべきなのに動いた」「つかみ損ね」に分ける

### 5.2 結果

| 区分 | 成功 |
|---|---|
| 基本 | 30/30 |
| 言い換え | 30/30 |
| 複数 | 25/25 |
| 位置関係 | 25/25 |
| 実行できない/曖昧 | 25/30 |
| 合計 | 135/140 |

- 1回の計画にかかった時間：平均 3.2秒
- つかむ点の誤差：平均 0.24cm・最大 0.5cm
- API 費用：1回 約1.4円（入力 約1,500・出力 約130トークン）

## 6. 考察

- **真上1枚の画像の限界**：「ボールを青い皿へ」で、Claude は緑の円柱を「緑のボール」として運んだ。真上からは円柱が円に見えるため。失敗5件はすべてこの指示で、5配置とも同じ誤りだった。〔要記入：横からのカメラを足す・形を尋ね返す などの改善案〕
- **指示の曖昧さ**：「箱を青い皿へ」は、箱1つとも全部とも読める。5配置のうち3回は「どちらを（または両方を）運ぶのか決められない」と返し、2回は箱を2つとも運んだ。どちらも正解として扱った。
- **僅差の配置**：140回中2回、Claude は「緑の玉と赤い箱はロボットの根元からの距離がほぼ同じで、どちらが一番近い物か決められません」のように保留した。実測の差は 0.1cm と 0.4cm で、人が見ても決められない配置だった。
